Run coding agents as a graph, not a loop.

A node is a subprocess. An edge is a file. The exit code is the contract. Works with the agent CLI you already have — Claude Code, Codex, OpenCode, Kiro, Gemini, Cursor, Amp or aider.

This is the whole idea

Two nodes. The first has an agent and write access. The second is a test command whose exit code decides whether the work was any good.

[agents.dev]
argv = ["claude", "-p", "--permission-mode", "acceptEdits"]

[nodes.implement]
agent   = "dev"
isolate = true                  # its own git worktree and branch
prompt  = "Add request-id logging to the HTTP layer."

[nodes.verify]
needs  = ["implement"]
agent  = "shell"
gate   = true                   # a failure here halts the graph
prompt = "npm test"
$ python geng.py run graph.toml

wave 1  (1 node(s), 4 at a time)
  ok   implement
wave 2  (1 node(s), 4 at a time)
  ok   verify

2/2 ok, 0 failed, 0 skipped

Swap claude -p for codex exec and nothing else changes. That one line is the whole portability story.

What it actually does

The exit code is authoritative, never parsed output
Only Gemini and Kiro publish exit-code tables. Cursor emits no valid JSON at all when it fails; Kiro and aider have no JSON mode. A runner that parses stdout to decide success is broken on arrival.
Files carry state between nodes, not context windows
Each node's stdout lands in .geng/out/<node>.txt and is substituted into dependent prompts as {node}. Referencing a node you did not declare is a hard error, so the graph cannot lie about what flows where.
Isolated nodes get their own git worktree and branch
Two nodes can edit the same file concurrently without touching each other or your checkout. Work is committed only if the node succeeded, so a failed half-edit can never look like something reviewable.
Resume is keyed on content
sha256(id + prompt + argv + upstream keys). Edit one prompt and --resume re-runs exactly that node and its dependents.
Gates are commands, not opinions
A gate node runs your test suite, type checker or linter. It cannot be argued out of failing, and it stops the graph when it does.
One file, no dependencies
Python 3.11+ standard library only. Drop it next to a repo, delete it when you are done. There is deliberately no pip install.

Use the harness you already have

Every one of these exposes a non-interactive command and an exit code, which is all geng needs.

A read-only reviewer is an adapter, not an instruction. A node given no write tools cannot “helpfully” fix the thing it was asked to judge — ["claude","-p","--allowedTools","Read,Grep,Glob"].

When not to use this

Most work does not need a graph, and on this point the people selling the idea agree with the sceptics. Reach for one on exactly three triggers:

1. Context rot
A single agent's window is hitting 300–500k tokens per iteration.
2. Independent review
The stakes are high enough that the author must not be the judge.
3. Wall-clock
Genuinely independent subtasks are running one after another.
Otherwise, keep your loop. A graph costs you three prompts to maintain instead of one, a state schema between nodes, and a new class of routing bugs. Agents burn roughly 4× the tokens of chat and multi-agent systems roughly 15×. Anthropic's own guidance: “most coding tasks involve fewer truly parallelizable tasks than research.” Your review bandwidth, not the tool's concurrency limit, is the real ceiling.

Run it in 60 seconds

You do not need an AI agent installed. The bundled example uses Python subprocesses as its agents, so it runs anywhere.

  1. Clone and run 
    git clone https://github.com/AdityaIndoori/graph-engineering
cd graph-engineering
python geng.py run examples/smoke.toml
    You should see 6/6 ok, 0 failed, 0 skipped. Three nodes ran in parallel, a fourth joined their output, a gate checked it, and a deliberately flaky node retried until it passed.
  2. Run it again, cached 
    python geng.py run examples/smoke.toml --resume
    Every node reports cached, in about a fifth of a second. Change one prompt and only that node and its dependents re-run.
  3. See the shape without executing anything 
    python geng.py plan examples/smoke.toml
    Prints a Mermaid diagram plus the execution waves. Then read the tutorial, which builds a graph from an empty file and explains every line. --dry-run shows the exact argv each node would execute, and changes nothing.

Three worked examples

Ship a feature you would actually merge
plan (read-only) → implement (own worktree) → test suite as a gate → two reviewers on different models → you decide.
A rename across many packages
Three isolated nodes, one owner per package, one typecheck && test barrier, then a read-only audit for missed callsites.
Hunt a flaky test
Reproduce ×200 as a gate before theorising, three competing read-only hypotheses, one writer, then the same check inverted to prove it is gone.

The last two show the shape worth internalising: parallelise reading and verifying, serialise writing and deciding.

Proof, not claims

51 tests run on Linux, macOS and Windows across Python 3.11–3.13. They assert the properties that would otherwise just be marketing:

  • editing one prompt invalidates that node and its descendants, nothing else
  • a failed gate halts the graph; dependents are skipped, not silently run
  • two isolated nodes writing the same file commit to separate branches while the main checkout stays untouched
  • a failed isolated node publishes no commit
  • a second concurrent run is refused rather than corrupting shared state
  • --dry-run creates no artifacts, no state and no worktrees

Questions you are probably about to ask

Is “graph engineering” just a rename?
Mostly, yes. The term is days old and came from a tweet; the structure is 19 months older, and Anthropic ships it as “dynamic workflows” without using the word. The one genuinely new part is setting an agent's capabilities per node. Full background.
Why not LangGraph, Temporal, Make or GitHub Actions?
Use them if you already run them — they are all more capable. geng exists because none of them is a single file you drop next to a repo with no infrastructure at all.
Do I need git?
Only for isolate = true nodes. Everything else works without it, and the test suite skips the git tests when it is absent.
Why is there no pip install?
Because the pitch is one file with no dependencies. Publishing a package would contradict it.
Can it run agents from different vendors in one graph?
Yes, and that is the point of the review nodes. Define two adapters and give one node each — a second model is the cheapest defence against correlated error.
Is a graph spec safe to run from someone else?
No more than a Makefile is. A spec is executable code; treat it that way. See SECURITY.md.
