A small tool for people who code with AI

Give an AI one job
at a time.

Ask an AI to do a big coding task all at once and two things go wrong: it loses track of what it did, and then it tells you everything went fine. geng splits the task into small steps and puts a real test in charge of deciding whether it worked.

Show me the problem GitHub

PART 1 / WHAT GOES WRONG

Say you ask an AI to
build a refund button.

Refunds send real money back to a customer, so it has rules. The order must exist. It must be recent enough. The customer must not have been refunded already.

So you write one long instruction: check all of these things, and if they pass, send the refund. You hand the AI the code, the rules, and the ability to move money. Then you let it work.

WHAT ACTUALLY HAPPENS

the AIreading, writing, and checking its own work
its memory of this taskfull
↻ attempt 4, still going
ALL DONEsaid by the same AI that wrote it

THE TWO PROBLEMS

1. It runs out of room. An AI can only hold so much of a conversation at once. Every attempt adds more. By attempt four it has genuinely forgotten what it decided in attempt one, so it starts contradicting itself.

2. It marks its own homework. The same AI that wrote the refund code is the one deciding whether the refund code is correct. It says yes. It usually says yes.

The bar is the AI's working memory filling up. The stamp lands while the bar is full, which is the whole problem in one picture.

And there is a third thing, quieter and worse. To do that job in one go, the AI needed the power to send refunds the entire time, including while it was still figuring out whether a refund was allowed.

You gave it the keys and a note asking it to be careful.

PART 2 / THE FIX

Split it into steps, and
hand out tools per step.

Same refund job, done as two separate runs of the AI instead of one. The first decides. The second acts. And here is the important part: the first one does not have the refund tool at all.

STEP 1 / DECIDE

+ look up the order
+ look up the customer
× send a refund
CHECK
allowed?

STEP 2 / ACT

+ look up the order
+ send a refund

Watch the red row appear. Step 1 physically cannot send money, however confused it gets. That ability shows up in step 2, only after the check in the middle passed.

Compare the two versions honestly. In the first, the AI is asked to behave. In the second, misbehaving is not available. That is the difference between a rule and a locked door, and it is the real reason to bother with any of this.

Both problems from Part 1 are gone too. Each step starts with a clean memory, holding only what it was handed. And the check in the middle is not an AI having an opinion, it is a program: it runs your tests and either passes or fails.

PART 3 / FOUR WORDS

Names for what you
have already seen.

You understood the idea from the two pictures. These are just the labels, so the rest of the page has something to call them.

STEP

One run of one thing

“Decide” was a step. Running your tests was a step. It can be an AI or an ordinary program.

HAND-OFF

A saved file

A step's answer gets written to a file, and the next step's instructions include that text. You can open it and read it.

VERDICT

A number, not an opinion

Programs report 0 when they finish fine, and something else when they do not. geng believes that number.

GATE

A step that can stop everything

The “CHECK / allowed?” box. Mark a step as a gate and a failure there halts the whole run.

Why a number and not the AI's own summary of how it went? Because Cursor prints nothing readable when it breaks, Kiro and aider have no summary option at all, and Claude, Codex and Gemini each use a different format. All nine tools report the number. It is the one thing they agree on, which is why geng works with any of them.

PART 4 / WRITING IT DOWN

The whole thing is
one small text file.

You list your steps in a plain text file, and geng runs them in order. Here is the refund example from Part 2, written out. Read the comments in grey and it should say something you already understand.

refund.toml

# Describe a way of running an AI. This one can
# read files, but has no power to send money.
[agents.checker]
argv = ["claude", "-p", "--allowedTools", "Read"]

# A plain command, not an AI.
[agents.shell]
argv = ["bash", "-lc", "{prompt}"]

# Step one: decide. No refund tool here.
[nodes.decide]
agent  = "checker"
prompt = "Is order 4471 refundable? Answer YES or NO."

# Step two: the check. If it fails, stop.
[nodes.tests]
needs  = ["decide"]  # wait for step one
agent  = "shell"
gate   = true        # the stop sign
prompt = "npm test"

The word geng uses for a step is node, which is why the headings say [nodes.decide].

What you see when you run it

$ python geng.py run refund.toml

wave 1  (1 node(s), 4 at a time)
  ok   decide

wave 2  (1 node(s), 4 at a time)
  FAIL tests exit=1 .geng/log/tests.log

halted: gate node(s) failed: tests

The tests failed, so geng stopped instead of carrying on to anything that touches money. If they had passed, it would have moved to the next step. “Wave” is just geng's word for a round of steps.

Swap claude for the name of whichever AI tool you use, and nothing else in the file changes.

PART 5 / YOUR TURN

Run one yourself,
with no AI needed.

You need Python and nothing else. The example below fakes its AI steps with tiny Python snippets, so you can watch the machinery work without signing up for anything or spending a cent.

git clone https://github.com/AdityaIndoori/graph-engineering
cd graph-engineering
python geng.py run examples/smoke.toml

You should see 6/6 ok. Six steps ran, three of them at the same time, one gate checked the result, and one step deliberately failed twice before working, to show you what a retry looks like.

That is the whole thing. You read the output, and that is all you have to do. Nothing is running in the background afterwards, and nothing was installed.

Then run the exact same command again. Everything now reports cached in under a second, because geng wrote down which steps already worked and does not redo them. Open examples/smoke.toml in any text editor, change one of the messages, run it a third time, and watch only that step and the ones after it repeat.

WHEN A STEP FAILS

It prints FAIL along with the path to a log file. Open that file: it holds the exact command that ran and everything the command printed, which is nearly always enough to see what went wrong.

PART 6 / A BONUS

Steps that do not wait
on each other run together.

You did not ask for this, you get it anyway. If three steps do not need each other's answers, geng starts all three at once and only waits when something actually depends on something else.

ROUND 1
check the login code
check the database code
check the docs
ROUND 2
write one report from all three
ROUND 3
run the tests
three 2-second steps together: 2.3s one after another: 6s

Round 2 needs all three answers, so it waits. Round 3 is the gate. geng works out the rounds for you from what each step says it needs.

PART 7 / KEEPING THINGS SAFE

Two AIs editing one file
without ruining it.

If two steps edit the same file at the same time, they overwrite each other and you get nonsense. So geng can give a step its own private copy of your project to work in.

WHY THIS IS EASY

If you use git to store your code, it already knows how to keep several copies of a project side by side. geng just asks git to make one per step. If you do not use git, skip this part: everything else still works.

copy for step A editing
copy for step B editing
your own files not touched

Both steps write freely in their own copy. Your files stay exactly as you left them, and a step that fails leaves nothing behind, so a broken attempt never looks like finished work.

Afterwards you look at each copy and keep the one you like.

How

Two commands worth knowing first

python geng.py plan graph.toml            # draws the steps, runs nothing
python geng.py run graph.toml --dry-run  # shows the exact commands, runs nothing

Both of these change nothing and cost nothing. Use the second one before any real run: it prints exactly what each step would do, which is your last chance to notice a mistake.

PART 9 / BE HONEST

Most jobs do not
need any of this.

If you are asking an AI to fix one function or write one file, just ask it. Splitting that into steps is extra work for no gain, and this page is not trying to talk you into it.

It starts paying off in three situations:

1

The job is too big to remember

Many files, many decisions, and the AI keeps forgetting earlier ones.

2

You need a real check

It matters too much to let the AI that wrote it be the one to approve it.

3

You are waiting around

Jobs that have nothing to do with each other are running one by one.

And a trap worth knowing about. Think of asking ten classmates to check your homework, except all ten copied from the same wrong textbook. They will all agree with you, and it will feel like ten confirmations. It is really only one.

AI steps do exactly this. Ten steps using the same AI, reading the same wrong information, reach the same wrong answer and agree. So the deciding step should be a real test rather than another AI, and if you do want a second opinion, get it from a different AI.

Two other honest costs: running several AI steps costs several times what asking once costs, and you still have to read what they did. That reading is usually the real limit, not the tool.

PART 10 / DOES IT ACTUALLY WORK

53 automatic tests say yes.

These run on Windows, Mac and Linux every time the code changes. They check the promises made on this page, so you do not have to take my word for any of them:

  • Change one step's instructions and only that step, plus whatever came after it, runs again.
  • When a gate fails, everything after it is skipped instead of quietly running anyway.
  • Two steps writing the same file end up in separate copies, and your own files are untouched.
  • A step that fails leaves nothing saved, so you cannot mistake it for finished work.
  • Starting a second run while one is going is refused, rather than scrambling both.
  • --dry-run genuinely writes nothing at all.

Short answers

Questions people
actually ask.

What if I do not have Python?
Install it from python.org, version 3.11 or newer. That is the only thing geng needs. There is no package to install after that, on purpose: geng is a single file you copy next to your project and delete when you are done.
Can I use this with ChatGPT?
Not the website, no. geng runs programs, so it needs an AI that runs as a command on your computer. The nine in the list above all do. If you only use AI through a browser tab, this tool has nothing to drive.
How do I know if the file I wrote is correct?
Run python geng.py plan yourfile.toml. It draws your steps and runs nothing, and it refuses the file with an error if you referred to a step that does not exist or made two steps wait on each other forever. Then --dry-run shows the exact commands before any of them happen.
What does it look like when something goes wrong?
The failing step prints FAIL with the path to a log file, and that file holds the exact command it ran and everything the command printed. Fix the cause, run the same command again, and the steps that already worked are skipped.
What does it cost?
geng is free. The AI steps cost whatever your AI tool charges, and running four steps costs about four times running one. You can cap how many run at once, and --dry-run costs nothing at all.
Do I need to know git?
Only for the private-copies idea in Part 7. Everything else works without it.
Is this just a fancy name for something old?
Honestly, mostly. People started calling this “graph engineering” a few weeks ago, but the shape of it is years old and bigger tools do it too. The genuinely useful part is handing out tools per step, which is Part 2. Longer version.
Is it safe to run a file someone sent me?
No safer than running any script a stranger sends you. These files run real commands on your computer, so read one before you run it.
